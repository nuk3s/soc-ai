# soc-ai 1.5.1

1.5.1 is a review release. A line-by-line review of the whole repository ran against 1.5.0: the
agent's evidence gates, the Oracle redaction, the egress guard, the tools, the store and its
migrations, the installer, the CI, the docs and the console. It produced 61 fixes. Each fix is pinned
by a test that failed before it. The release was run on a live attack range and on a production
grid before it shipped. The full list is in [CHANGELOG.md](https://github.com/nuk3s/soc-ai/blob/v1.5.1/CHANGELOG.md) under 1.5.1.

## What changed

### A verdict rests on less that is not evidence

- A model-authored `resolution` marker in a report no longer stores a real verdict as a pipeline
  failure. The field is stripped on every synthesis path.
- A short wire string on the alert's own flow (an SMB file named `alert`, a four-letter RPC name)
  no longer grounds a verdict by itself. Whole-word from 5 characters, substring from 8.
- A hunt finding cannot cite a tool error, a duplicate-call stop or a prefetch hint as evidence.
- An attack-class alert that matches a housekeeping template no longer settles as a false positive
  with zero tool calls. It goes to the investigator.
- A pivot lookback of zero, negative or over 30 days is refused before the "self-originated"
  all-clear can fire.

### Less leaves the building

- An internal name behind a port (`dc01.corp.local:443`, `finance-pc:445`) is refused by the web
  search and the crawler. The targeted dispatch applies the same discovered-host set as the
  interactive tools, and a model-supplied argument can no longer disable the guard.
- The Oracle sanitizer tokenises Windows computer names, NTLM server names and Kerberos principals,
  and it re-fangs `10[.]0[.]0[.]5` and `hxxp://` before it matches. A learned internal host that
  recurs defanged in a runbook is tokenised, not refused.
- `ORACLE_INTERNAL_SUFFIXES` entries without a leading dot, or in upper case, now match.
- An Oracle confidence that is NaN or out of range is rejected. It used to clamp to 1.0.
- Every MCP tool call writes an audit row.

### The store and the tools tell the truth

- The startup migration chain runs in one transaction. A revision that fails half-way leaves the
  store as it found it. The orphan check runs only when a revision runs, and a store that already
  held an orphan keeps starting, with a warning.
- Migration 0052 indexes the bell's completed-runs read and the unread shadow-hit count. On a
  383 MB production store the bell answers in about 40 ms.
- A tcpdump failure on the sensor is reported as an error. It used to read as "no packets matched".
  The capture window is capped at 60 minutes and the ring-file scan at 100 files.
- A corrupt or empty feed file is not loaded, and a feed body is validated before it replaces the
  live file. An empty feed no longer reads as clean.
- A backup archive is created private and never contains the bootstrap credential.
- A webhook send is retried on a connect failure only. A read timeout is not retried, because the
  receiver may have taken the page.

### Hunting

- Role priors on the process and logon dimensions find the host's role. They key on `host.name`
  and the dossier keyed roles on the IP, so five of the nine shipped role priors were blind.
- A host that went silent is a collapsed-rate departure, and the observation says the host was not
  seen at all in the window.
- A dimension that no plane on the grid carries reads as blind, not as quiet.
- One lead starts one hunt, when the click and the loop's wake land together. The loop pages past
  leads that cite nothing. Deleting a hunt releases the lead and the fired condition that pointed at
  it. A reopened lead can be promoted again. A hunt's chat recovers from an unclean restart.
- Re-triaging an alert as a false positive closes or reshapes the lead that alert formed.

### The console

- Clearing a stored API key or the webhook URL asks for a confirmation click.
- A failed acknowledge, escalate or assign shows a red toast that stays. A failed group read shows a
  retry card, never "No events in window". `?view=mine` and the palette's My queue land on the Mine
  chip. Leaving the screen stops the background poll.
- The fitness chip and the full check refuse to grade a model that is staged and not applied.
- Bell rows, investigation rows and sort headers work from the keyboard. A click anywhere on a bell
  row still opens it.
- The lead page reads finished hunts, failed reads and stale hunt rows honestly, and the Hunt-again
  confirm links the hunt it names.
- The Egress policy page lists MISP and the release check. The Data sources page reads "not
  configured" when a key is blank, and the MaxMind row no longer asks for a key that nothing uses.

### The installer and the build

- `setup.sh` no longer copies conf comments into `.env`, quotes every value, reads the port back
  from the conf, and leaves the TLS key readable by the container.
- `pydantic-ai-slim[openai]` replaces the full provider set: 80 fewer packages in the image. `mcp` is
  capped below 2. Advisory-flagged pins are bumped and a dependency audit job runs in CI.
- A blank `SOC_AI_TLS_CERT`, `SOC_AI_TLS_KEY` or API key reads as unset. `LOG_LEVEL` is validated
  at load.

## Upgrade notes

- Migration 0052 runs at the first start. It adds three indexes and changes no rows.
- The Docker image rebuilds from the new lock. A source install needs `uv sync` before the restart:
  `pip install -e . --no-deps` does not move the pins.
- `LOG_LEVEL` must be a Python logging level name (`DEBUG`, `INFO`, `WARNING`, `ERROR`,
  `CRITICAL`). Any other value refuses to start.
- With `API_AUTH_REQUIRED=false`, creating a user or changing a role now needs an admin session, the
  same as a password reset.
- The full test suite runs in about 3 minutes under `pytest -n 4 --dist loadfile`.

## Known limits

- The note that names why a dimension is blind is printed by `soc-ai priors` only. The API and the
  console show the count.
- The collapsed-rate analytic keeps firing for a host that left the estate until its baseline ages
  out, 30 days at most.
- A role prior on a `host.name` dimension measures only after the next profile rebuild.
